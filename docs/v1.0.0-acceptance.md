# v1.0.0 acceptance contract

This checklist separates producer release acceptance from later consumer integration. A candidate is not a Forgejo release until every producer gate below is revision-matched and passed.

## Product and compatibility

- WEBHOOK-001 through WEBHOOK-009 pass without expanding alert authority or moving host-owned lifecycle policy into the process.
- Binary, canonical manifest, archive directory, release bundle, release notes, annotated tag, and Forgejo stable Release identify exactly 1.0.0 / v1.0.0.
- Control remains gotth.extensions.control 1.0 and notification remains gotth.mail.interface.notification 1.0.
- The protected runtime-binding v1 document contains canonical grant and host-profile data plus manifest/grant/session digests. Startup reruns gotth-extensions v1 negotiation, compares all authoritative identity/digest values, and retains that session. Handshake, legacy capability discovery, and SendAlert cannot widen it.
- gotth-extensions v1.0.0 and gotth-sdk v1.0.0 remain exact selections without replace; source, descriptor, Go package, and RPC-path bindings pass.

## RPC and security

- A unary interceptor rejects every RPC lacking a deadline or the exact service token before its handler runs. Real Unix-gRPC tests cover all seven RPCs.
- Each handler then validates its normal request admission. SendPrompt performs deadline, token, and correlation-ID admission before returning Unimplemented.
- SendAlert requires negotiated notification.alert.send authority. Empty or narrowed negotiated capability/interface sets remain narrow.
- Full, race, repeat, shuffled-race, hostile-input, bounded fuzz, process, govulncheck, and gitleaks checks pass on the candidate revision. HTTPS tests use only isolated TLS receivers.

## Artifact and provenance

A clean-tree build emits exactly these assets into a previously absent output path:

- gotth-extension-webhook-1.0.0-linux-amd64.tar.gz;
- gotth-extension-webhook-1.0.0-linux-amd64.spdx.json;
- gotth-extension-webhook-1.0.0-linux-amd64.intoto.jsonl;
- SHA256SUMS covering the preceding three assets.

The builder exports one resolved HEAD commit and executes the exported builder and source, never the mutable checkout. It disables ambient Go workspace/config/flags/toolchain/experiment/FIPS selection, rejects module replacements, uses readonly module mode and no network proxy, fixes GOAMD64, and verifies cached modules. Two builds from the same revision and commit epoch are byte-identical.

The SPDX package checksum is the SHA-256 of the downloadLocation module ZIP. The exact Go h1 directory hash is retained separately. Provenance records both checksum semantics, source commit/tree and tracked-source manifest, exact linked graph, target and build flags. Optional SLSA execution timestamps and invocation IDs are omitted because deterministic output cannot truthfully encode invocation-specific values.

Ordinary relative output paths resolve against the caller's working directory and are regression-tested against an absolute-path build for exact asset equality. The four final files are synchronized in a same-filesystem staging directory and exposed by one directory rename. A pre-rename failure leaves no output directory. A post-rename synchronization, re-hash, or lock-cleanup failure may leave a complete but unaccepted output directory and/or lock; operators must inspect and verify it rather than treating command failure as publication or deleting it blindly. Existing output is never an accepted target.

## Producer review and Forgejo publication

- Two fresh independent reviews are clean for the final revision and bundle.
- The annotated v1.0.0 tag peels to that reviewed commit.
- The canonical non-draft stable Forgejo Release contains exactly the four verified assets. scripts/check-v1-release-closeout.sh verifies tag identity, metadata, authenticated downloads, and byte equality to the local bundle.
- Publication is separately authorized. This checklist does not authorize a tag, push, upload, Release, deployment, or production webhook.

GitHub publication/parity is Bryce's distribution handoff after canonical Forgejo release. It is not a Forgejo producer-release blocker.

## Post-release consumer integration

After all four extension v1 releases, Mail may add the exact released digest through its normal reviewed consumer change and run the unmodified production-supervisor A→B→A lifecycle. The extension repository does not change, patch, overlay, or bypass Mail to manufacture that evidence. This later Mail acceptance is required for consumer adoption, not for publishing this producer artifact.

## Not v1.0.0 gates

Additional targets, signing beyond authenticated hosted-release publication, automatic dependency updates, receiver provisioning, arbitrary payloads, prompts, mutations, and generic event-bus work are future proposals.
